# README And AGENTS Corpus Protocol

## Purpose

This protocol keeps inherited agent context small without erasing useful human
documentation. It governs the role boundary and review evidence for tracked
`README.md` and `AGENTS.md` surfaces in `Agents-of-Abyss`.

It does not decide center doctrine, mechanic meaning, proof, runtime state, or
sibling-owner truth. Those claims stay with their authored owner sources.

## Surface roles

`AGENTS.md` is inherited route law. The nearest applicable card may carry:

- scope and owner boundary;
- the local delta from parent guidance;
- task-relevant source routes;
- local risks and stop-lines;
- a compact validation route;
- closeout and handoff expectations.

It should not carry a human overview, changelog, complete package inventory,
large command matrix, full schema catalog, or copied source doctrine. The
`Read before editing` section is a conditional route selector: it names a
surface only when that surface can change the interpretation of work in this
lane. It must not require the nearest README merely because one exists.

`README.md` is an on-demand human or public surface. It may explain purpose,
usage, examples, navigation, provenance, compatibility, or the relationship
between stronger sources. It is not automatically part of agent context and it
does not become owner authority by filename.

Authored owner sources and contracts define meaning. Schemas, manifests, and
registries define machine topology. `VALIDATION.md`, validated manifests,
runners, and other named procedure surfaces own exact procedure. Generated
views remain reproducible derivatives with explicit source return.

## Root exception

Keep the repository root `README.md` by default. It is the civic and public
front door named by `docs/ROOT_SURFACE_LAW.md` and
`docs/START_HERE_ROUTE_CONTRACT.md`.

A proposal to remove or replace it needs a separately accepted root-surface
decision and evidence that public, contributor, package-host, and incoming-link
functions survive. Corpus size or similarity is not that evidence.

## Dispositions

Every in-scope README and AGENTS file receives one reviewed disposition before
the owner pass closes:

- `keep` when the surface has a distinct current role;
- `slim/rewrite` when the role is valid but the surface repeats inherited or
  stronger material;
- `merge into parent` when one parent surface can preserve the unique route
  without weakening locality;
- `move` when content belongs in an owner source, contract, manifest, registry,
  validation surface, roadmap, changelog, or provenance bridge;
- `generate` when the file is a reproducible read model rather than authored
  truth;
- `delete obsolete placeholder` when no implemented, human, compatibility,
  provenance, fixture, or route function remains;
- `blocked pending evidence` when ownership, callers, uniqueness, generation,
  or compatibility cannot be established safely.

Pairing, size, similarity, or an apparently thin body never decides a
disposition by itself.

## Required review evidence

The owner review accounts for:

- owner and exact base revision;
- inherited AGENTS-chain bytes and README read fanout;
- unique human/public entry, usage, example, navigation, and provenance value;
- incoming Markdown, registry, manifest, builder, validator, generated-view,
  packaging, and fixture references;
- duplication against parent guidance and stronger source surfaces;
- chosen disposition, affected callers, checks, and remaining uncertainty.

Generated, vendor, fixture, archive, and legacy trees stay visible as distinct
classes. A generated README is changed through its builder. A fixture is
changed only with the test contract. Legacy and provenance routes are not
deleted as if they were empty current documentation.

## Change law

Slim an AGENTS card by removing repeated parent law, unconditional reading,
catalogs, and exact procedure only after the surviving owner source and route
are named. Keep the stop-line nearest to the risk when no stronger source or
validator can preserve it.

Slim or remove a README only after its unique human or compatibility function
is absent or moved. Update links, indexes, registries, builders, generated
views, validators, and tests in the same owner change. Broken callers are not a
post-merge cleanup item.

Do not move README explanation into AGENTS merely to lower the README count.
Do not move AGENTS stop-lines into README merely to lower prompt bytes.

## Measurement contract

Measure before and after:

- tracked AGENTS and README count and bytes;
- inherited-chain median, p95, maximum, and budget violations;
- unconditional README-read count and byte fanout;
- cards carrying fenced procedure or large repeated blocks;
- human/public navigation coverage and broken local links.

These measurements expose pressure and regressions. They do not determine
semantic value, token savings, CI savings, proof, or acceptance by themselves.

## Validation and closeout

Use the route named by the nearest `AGENTS.md`. At owner closeout, run AGENTS
mesh, Markdown/link, generated-freshness, decision-index, and release checks
affected by the dispositions. Compare the final tracked corpus with the review
ledger and account for every new, renamed, or removed README/AGENTS path.

The owner branch may be prepared and reviewed independently, but it must not be
merged before the cross-repository README/AGENTS corpus barrier permits the
single dependency-ordered merge wave.
